# Terraform

The canonical infrastructure implementation. Everything deployed to AWS is
created here — see [ADR-0001](../../docs/adr/0001-terraform-is-canonical.md).

```
environments/demo/     The only environment. Composes the modules and makes the
                       demo-specific choices: small instances, one NAT gateway,
                       no Multi-AZ, no deletion protection.
modules/
  network/             VPC across two AZs, public and private subnets, NAT,
                       route tables, an S3 gateway endpoint, and the shared
                       workload security group that data-tier rules reference.
  eks/                 Control plane, managed node group, add-ons, and one IAM
                       role per application via EKS Pod Identity.
  database/            RDS PostgreSQL, parameter group, generated password
                       written to Secrets Manager.
  messaging/           MSK Serverless and Amazon MQ for RabbitMQ.
  platform/            ECR repositories with immutable tags and lifecycle
                       policies, CloudWatch log groups, database alarms.
```

## Commands

```bash
make tf-validate    # fmt + validate; needs no AWS credentials
make tf-plan
make tf-apply       # costs money
make destroy
```

## Conventions

**Plain resources, not the community modules.** The community EKS and VPC modules
are the right answer for a team maintaining real clusters. Here the point is that
a reader can see what an EKS-ready VPC is made of, which a module call hides.

**No secrets in variables, state or outputs.** Passwords are generated by
`random_password` and written directly to Secrets Manager. Outputs name the
secret rather than reproducing it, so `terraform output` cannot leak a password
into a terminal or a CI log.

**Production settings are variables with the trade written next to them.**
`multi_az`, `nat_gateway_count`, `rabbitmq_deployment_mode`, `deletion_protection`
and `skip_final_snapshot` all default to the cheap demo value and are commented
with what production wants.

**Everything is tagged** `Project=open-aviation-telemetry`, so what this project
owns can be listed with one API call after a destroy.

## Remote state

The S3 backend is written out and commented in `environments/demo/main.tf`. Local
state is acceptable for one person running a demonstration and is not acceptable
for a team: two applies race, and the state file lives on a laptop. Create the
bucket, then uncomment.
